- Components are made with the composition method of abstraction.
  - A component is made of other components which are made of other components and so on and so forth until the components are too simple to be broken up or all the logic msut be in that one place.
- Basically anything that is dynamic content should be tested ideally.
  - in terms of frontend, anything is mostly visual and testing it is really not helpful at all since the true test is actually looking at it.
- Have to use regex's for tests with `\ *regular expr* \` because then the test doesn't properly find the elements it looks for
- Generally, everything 'interactable' in the frontend uses the Next.js 'use client' indicator.
- The best way to go about making my own components is by using very thoroughly tested and refined components from libraries like shadcn and then changing them accordingly and individually if necessary so it fits our UI theme and format.
